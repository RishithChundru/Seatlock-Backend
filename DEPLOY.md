# Deploying Seatlock

```
Vercel (Next.js) ──HTTPS──▶ Render (Spring Boot, Docker) ──▶ Neon (PostgreSQL)
                                     ├──────────────────────▶ Upstash (Redis, TLS)
                                     └──────────────────────▶ CloudAMQP (RabbitMQ, TLS)
GitHub Actions: test + docker build ──(main only, both green)──▶ Render deploy hook
Vercel GitHub integration: preview per PR, production on main
```

All services have free tiers. Pick the same region everywhere (Singapore / `ap-southeast-1` is closest to India) to keep latency low.

You need accounts on: GitHub, [Neon](https://neon.tech), [Upstash](https://upstash.com), [CloudAMQP](https://www.cloudamqp.com), [Render](https://render.com), [Vercel](https://vercel.com). Sign in to each with GitHub.

Keep a scratch note open while you go: you'll collect 6 values (DB URL, DB user, DB password, Redis URL, RabbitMQ URL, admin password) and paste them into Render in step 4. **Never commit them.**

---

## 1. PostgreSQL on Neon

1. **New Project** → name `seatlock`, region **AWS Asia Pacific (Singapore)**, Postgres 17.
2. On the project dashboard, open **Connect**. Turn **Connection pooling off** (Spring already pools connections) and copy the connection string. It looks like:
   `postgresql://neondb_owner:AbC123@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
3. Split it into the three values Spring needs:

   | Variable | Value |
   |---|---|
   | `DB_URL` | `jdbc:postgresql://ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require` |
   | `DB_USER` | `neondb_owner` |
   | `DB_PASSWORD` | `AbC123` |

   (Add `jdbc:` in front, and remove `user:password@` from the middle.)

Tables are created automatically on first start.

## 2. Redis on Upstash

1. **Create Database** → name `seatlock`, type **Regional**, region **ap-southeast-1**, TLS on.
2. On the database page, copy the **Redis URL** that starts with `rediss://` (two s = TLS):
   `rediss://default:YOUR_PASSWORD@apn1-xxx.upstash.io:6379` → this is **`REDIS_URL`**.

## 3. RabbitMQ on CloudAMQP

1. **Create New Instance** → plan **Little Lemur (free)**, name `seatlock`, region **AWS ap-southeast-1** (or the closest offered).
2. Open the instance and copy the **AMQP URL**. Change `amqp://` to **`amqps://`** (TLS) if it isn't already:
   `amqps://abcdefgh:PASSWORD@puffin.rmq2.cloudamqp.com/abcdefgh` → this is **`RABBITMQ_URL`**.

The app declares its queues (`booking.confirmed`, `booking.confirmed.dlq`) on startup; you can watch them in CloudAMQP's **RabbitMQ Manager**.

## 4. Backend on Render

1. Make sure the latest code is pushed to `main` on GitHub.
2. Render dashboard → **New** → **Blueprint** → connect GitHub → pick **Seatlock-Backend**. Render reads [`render.yaml`](render.yaml).
3. It asks for the secret values. Fill them in:

   | Key | Value |
   |---|---|
   | `DB_URL`, `DB_USER`, `DB_PASSWORD` | from step 1 |
   | `REDIS_URL` | from step 2 |
   | `RABBITMQ_URL` | from step 3 |
   | `CORS_ORIGINS` | `http://localhost:3000` for now (you'll add the Vercel URL in step 7) |
   | `ADMIN_PASSWORD` | a strong password of your own; this becomes the password for `admin@seatlock.dev` |

   `JWT_SECRET` is generated by Render automatically.
4. Click **Apply**. The first deploy builds the Docker image (about 5 minutes).
5. When it's live, copy the service URL, e.g. `https://seatlock-api.onrender.com`, and open `https://seatlock-api.onrender.com/actuator/health`. It should show `{"status":"UP"}`. Also try `/api/events` (it should list 4 events).

If the deploy fails, open **Logs**. The usual causes are a typo in `DB_URL` (missing `jdbc:`), or `redis://` instead of `rediss://`.

## 5. Connect CI/CD to Render

`render.yaml` turns off Render's own auto-deploy, so only code that passes CI is deployed.

1. Render → `seatlock-api` → **Settings** → **Deploy Hook** → copy the URL (treat it like a password).
2. GitHub → **Seatlock-Backend** → **Settings** → **Environments** → **New environment** named `production` → **Add environment secret**:
   - Name: `RENDER_DEPLOY_HOOK_URL`
   - Value: the deploy hook URL
3. From now on, every push to `main` runs **Actions → CI/CD**: tests (real Postgres/Redis/RabbitMQ in containers), then the Docker build, then the deploy hook, which only runs if both pass. Pull requests run the checks but never deploy.

## 6. Frontend on Vercel

1. Vercel → **Add New… → Project** → import **Seatlock-Frontend**. The framework is detected as Next.js; keep the defaults.
2. **Environment Variables**: add
   - `NEXT_PUBLIC_API_URL` = your Render URL from step 4, **without** a trailing slash (e.g. `https://seatlock-api.onrender.com`)
3. **Deploy**. Copy the production URL, e.g. `https://seatlock-frontend.vercel.app`.

Vercel redeploys on every push to `main` and makes a preview URL for every PR. The frontend's GitHub Actions workflow (lint + build) runs alongside as the quality gate.

> `NEXT_PUBLIC_API_URL` is baked in at build time. If you change it, redeploy (Deployments → ⋯ → Redeploy).

## 7. Allow the frontend in CORS

Render → `seatlock-api` → **Environment** → edit `CORS_ORIGINS`:

```
https://seatlock-frontend.vercel.app,http://localhost:3000
```

Save. Render restarts the service.

## 8. Smoke test

1. Open the Vercel URL. Events load (the first request after idle can take ~50 s; see below).
2. **Sign in** → **Fill in demo account** → pick seats → **Book** → **Tickets** shows a ticket code within a few seconds (that's RabbitMQ working).
3. Sign out, sign in as `admin@seatlock.dev` with your `ADMIN_PASSWORD` → **Admin** → upload cover photos.
4. Optional: require CI before merging. GitHub → each repo → **Settings → Branches → Add rule** for `main` → **Require status checks to pass**.

## Day-to-day

```powershell
git add -A
git commit -m "Your change"
git push
```

- Backend: Actions runs the tests, and Render deploys if they pass (watch the **Actions** tab).
- Frontend: Vercel deploys, and Actions lints and builds.

## Good to know (free tiers)

- **Render free** services sleep after ~15 minutes idle; the next request wakes them in ~30–60 s. Before showing it to a recruiter, open the site a minute early, or upgrade to a paid instance.
- **Neon** suspends compute when idle and resumes on the next query (a second or two).
- **CloudAMQP Little Lemur** and **Upstash free** have message/command limits, far above what a demo uses.
- The schema is managed by Hibernate (`ddl-auto=update`). Before real users rely on the data, switch to Flyway migrations.
- If a secret leaks (JWT secret, DB password, deploy hook), rotate it in the provider and update it in Render or GitHub. Rotating `JWT_SECRET` signs everyone out.
- The admin password is only applied when the database is **first** seeded. To change it later, re-create the database or add a change-password feature.
